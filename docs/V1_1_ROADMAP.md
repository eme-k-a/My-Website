# Commit History v1.1: the museum up close

**Outcome.** A visitor can enter the museum, find any exhibit, inspect its artifact from any angle, understand what a physical detail says about Emeka's work, and return to the same place. The Volunteer & Leadership wing will tell two distinct stories: leading a developer community at SDSJ and delivering and maintaining NSBE MUN's public website.

**Starting point.** Stable v1.0.0 on `main`, commit `34b80d2`. The November 18 walkthrough covered 13 desktop stops, nine stories, both wings and the phone résumé exit. It found that the objects' explanations sit well below their introductory labels, the phone story covers the case, and the Projects doorway shows P2 before visitors enter at P1. The entrance ticket, paper labels, native scroll, optional wings and closing desk are strengths to preserve. See [existing backlog](FUTURE_IMPROVEMENTS.md), [architecture](ARCHITECTURE.md), and [experience spec](spec/EXPERIENCE.md).

## How changes ship

- Each numbered item below is a separate reviewable PR. Branch from the current `v1.1` tip (for example `museum/06-inspector`), target `v1.1` explicitly, record acceptance evidence in the description, and merge after relevant checks pass. Update this checklist in the delivery PR. Split an item if the change is too large to review independently.
- Use PR previews for review. Current CI runs on pull requests; a push to `v1.1` alone does not trigger the same workflow. Confirm the PR base and preview context before sharing. Keep deploy workflows and production targeting intact.
- Coordinate shared files (especially exhibit IDs, content schema and the story dialog) with active M7 work. Inspect and reuse compatible scaffolding after it lands; keep M7 maintenance and museum delivery independently reviewable.
- Emeka decides when the candidate is satisfactory. Opening any release PR to `main`, deploying production or tagging the release is a separate decision after his explicit go-ahead.

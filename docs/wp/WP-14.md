# WP-14: Dialog, routes, prerender

## Goal
Every exhibit's full story opens in one accessible native `<dialog>` (a right-hand panel on desktop, one full-height sheet on phones) with Newer and Older in catalogue order and "Copy link". Each exhibit has a real, prerendered page at `/exhibit/<id>/` with its own title, description, canonical URL and Open Graph tags, and its story readable with JavaScript off. History follows one rule set: opening pushes one entry so Back closes it, Newer and Older replace, closing a cold-loaded deep link replaces with `/`, and stop arrivals never touch the URL.

## Notes
- Crawlers drop hashes, so a shared hash link would unfurl as the home page. Real prerendered paths fix that and need no host rewrites.
- Closing a cold-loaded deep link with `history.back()` would throw the visitor off the site; only `state.inApp` entries may go back.
- If Newer and Older pushed entries, Back would walk through every exhibit read. They replace.
- Native `<dialog>` with `showModal()` gives the focus trap and Esc for free; the `cancel` event must route through `closeStory()` so history stays consistent.
- No drag-to-rotate on mobile: it fights the sheet and was cut. The sheet is one height.
- Rendering pauses while the phone sheet covers the screen (WP-16 reads the `data-sheet` flag), which saves battery on long reads.
- Durations of ongoing roles change monthly; visual baselines mask `dialog-duration`.

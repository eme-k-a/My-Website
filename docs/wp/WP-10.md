# WP-10: App shell

## Goal
The site works before and without the 3D gallery: a sub-2 KB boot script picks museum or classic mode before first paint; the prerendered page shows the recruiter fast path (name, current role, degree, Resume PDF, Email, Classic view) in the first phone viewport with or without JS; the app hydrates a HUD with the progress rail and Classic and PDF buttons, the stop cards, a story dialog skeleton and a live region, and lazy-loads the museum only after `load` plus idle. `/resume/` is a zero-JS classic resume that follows the system theme and prints on white; `404.html` and a `<noscript>` notice exist; browsers without WebGL2 land on `/resume/`.

## Notes
- A recruiter arriving from LinkedIn on a phone gives the page about 10 seconds. The hero, not the canvas, is the LCP element; the museum chunk is requested only after `load` plus idle (or first interaction) so it never competes with it.
- The inline boot script is allowed by a CSP hash computed by `scripts/headers.ts` from the final HTML. It must be byte-identical on every page that has it; do not template anything into it.
- Chromium 137 and later has no WebGL fallback without `--enable-unsafe-swiftshader`; real users on software renderers (llvmpipe, SwiftShader, Microsoft Basic Render Driver) get about 3 fps, so they go to `/resume/`. Tests bypass this with `?test=1`.
- Safari has no `deviceMemory`; coarse-pointer devices start at medium tier (`chooseTier`, WP-16 completes it).
- Every case has a DOM "Read the story" button; the 3D click is a convenience.
- `/resume/` follows the system theme; the gallery is always dark.
- Keep card heights stable between prerender and hydration (fixed-width date stamp areas, reserved loading row) so CLS stays at or below 0.02.

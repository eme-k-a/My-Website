# WP-34: Review automation

## Goal
One command, `npm run review`, produces a complete, reproducible review packet with no manual steps: screenshots of every stop and every story dialog on four viewports, `stats()` per stop, axe results per state and Lighthouse summaries, written to `review/runs/<date>/` with a scorecard template. R11 then scores it against the rubric and the previous round, files findings, and the PLAN §6 loop can run after every content change and monthly.

## Owner role
R8 QA & Test Automation (capture runner) with R11 Experience Reviewer (scorecard format, findings schema, loop protocol).

## Milestone and dependencies
M7. Must be merged first: WP-33 (v1 released). Parallel with: WP-35, WP-36. Feeds: every later review round and the `F-###` fix briefs.

## Inputs
- PLAN §6 (capture, score, file findings, fix, stop rules, after launch).
- `docs/ART_DIRECTION.md` §7 (rubric D1 to D6) and §10 (reference stills from G2 and G4).
- `tests/e2e/capture.spec.ts` and `helpers.ts`, `lighthouserc*.cjs`, `review/rubric.md`, `review/findings.json` (WP-19 format).

## Owned globs (exclusive)

## Commands
```sh
npm ci
export PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers
time npm run review
D=$(ls -d review/runs/*/ | sort | tail -1)
node -e "const s=require('./'+process.argv[1]+'summary.json');const v=Object.values(s.viewports);if(v.length!==4)throw new Error('viewports');for(const x of v){if(Object.keys(x.stops).length!==14||Object.keys(x.dialogs).length!==10)throw new Error('counts')}console.log('summary ok')" "$D"
npx vitest run --project unit scripts/review
```

## Acceptance
- A1. One command, no manual steps. Proof: `time npm run review`. Threshold: exit 0, under 15 minutes.
- A2. Complete packet. Proof: the `node -e` summary check. Threshold: `summary ok` (4 viewports, 13 stops and 9 dialogs each, stats and axe per state, Lighthouse scores present).
- A3. Scorecard and findings formats. Proof: files exist and the schema validates the current `review/findings.json`. Threshold: pass.

## Output
- Commits: `feat(review): capture runner`, `docs(review): scorecard template, findings schema and loop protocol`. Each ends with `WP: WP-34` and the attribution lines.
- `review/reports/WP-34.json` with the runtime and the first run folder.

## Size
M. A capture runner reusing existing helpers, plus formats.

## Notes
- Reviews compare against the previous round and the approved G2 and G4 reference stills; absolute scores from SwiftShader screenshots are unstable.
- Desktop at `tier=high` is what most desktop visitors see; Pixel 7 at medium is what phones see.
- Keep the runner deterministic (`?test=1`) so two runs on the same commit produce the same images.

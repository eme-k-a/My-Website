# WP-06: CI

## Goal
Every push and pull request runs the full pipeline on GitHub Actions: verify, build (with the PDF gate, budgets and copy checks), e2e, Lighthouse and the LaTeX one-page check. Production headers (CSP with the boot-script hash, cache rules) are generated into `dist/_headers`, and a tiny local server applies them so every test sees the real CSP. Copy and budget checks exist as scripts. Dependabot keeps the pinned stack moving in groups.

```sh
npm run verify
npm run build
ls -l dist/_headers && grep -E 'Content-Security-Policy|immutable' dist/_headers
PORT=$((4173 + ${N:-0})); npx tsx scripts/serve-dist.ts --port $PORT & SERVER=$!; sleep 1
curl -sI http://localhost:$PORT/ | grep -i '^content-security-policy'

kill $SERVER
npm run check:copy; echo "exit=$?"
RELEASE=1 npm run check:copy; echo "exit=$?"
npm run check:budgets

```

## Notes
- The inline boot script would be blocked by its own `script-src 'self'`; the hash in `_headers` is what lets production enter museum mode. Hash the exact bytes between `<script>` and `</script>` in the final HTML, after prerendering.
- `vite preview` ignores `_headers`, which is why every test goes through serve-dist: the CSP must be exercised in e2e, not only in production.
- Lighthouse launches Chrome without the SwiftShader flags by default; Chromium 137 and later then has no WebGL, the boot script picks classic, and Lighthouse scores the wrong page. The `chromeFlags` and `&mode=museum` prevent that; WP-29 adds the precheck that fails the job if the museum is not what Lighthouse sees.
- SwiftShader performance scores are noise: on `/` only accessibility, SEO, LCP and CLS will be hard gates (WP-29); on `/resume/` performance is a hard gate too.
- `@lhci/cli` uses its bundled lighthouse 12.6.1. Do not add `lighthouse` as a dependency.
- Netlify merges header rules whose paths overlap; never set the same header name in two overlapping rules.
- The phone regex will match strings in test fixtures if written literally. Build fixtures at runtime.
- CI baselines for screenshots are generated and compared only in CI (`update-baselines`), because SwiftShader output differs by CPU.

- R0 ruling (2026-10-15): `check:copy` with `RELEASE=1` must also fail while any `exhibit.draft` is true.

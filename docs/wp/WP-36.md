# WP-36: Scheduled maintenance

## Goal
The live site stays honest without anyone remembering to touch it: a weekly scheduled workflow rebuilds production so "On view now", durations and JSON-LD stay current (and fails loudly when a tense flag goes stale), smoke-tests production, checks external links and confirms the production PDF is one page, opening an issue on any failure. A dated maintenance checklist covers the changes no automation can make.

R10 DevOps & Release.

## Milestone and dependencies

## Commands
```sh
npm ci
npx vitest run --project unit scripts/check-links.test.ts
python3 -c "import yaml; yaml.safe_load(open('.github/workflows/scheduled.yml')); print('yaml ok')"
BUILD_DATE=2027-01-05 RELEASE=1 npm run build; echo "exit=$?"   # expected to fail until Verafin is past tense
# after merge to main (R0):
gh workflow run scheduled.yml --ref main && gh run list --workflow scheduled.yml --limit 1 --json conclusion,url
```

## Acceptance
- A1. Workflow valid. Proof: the `python3` line. Threshold: `yaml ok`.
- A2. Link checker. Proof: `check-links.test.ts`. Threshold: pass (fails on 404, warns on 999).
- A3. Stale tense is caught. Proof: `BUILD_DATE=2027-01-05 RELEASE=1 npm run build`. Threshold: exit 1 naming `verafin` (as long as content is still present tense).
- A4. Scheduled run succeeds on `main` (R0, after merge). Proof: `gh run list --workflow scheduled.yml`. Threshold: `success`.
- A5. Checklist. Proof: `docs/MAINTENANCE.md`. Threshold: all dated items present.

## Notes
- `current` is derived from the build date, so a site that is never rebuilt goes stale; the weekly rebuild is the fix.
- The January 2027 failure is intentional; it turns into an issue that tells R1 to run the content runbook.
- LinkedIn answers bots with status 999; treat it as a warning, not a broken link.

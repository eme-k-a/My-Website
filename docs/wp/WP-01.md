# WP-01: Scaffold

## Goal
The repo becomes a Vite + React + TypeScript project at its root, installed with npm from a committed lockfile with every version pinned per ARCHITECTURE §1, with ESLint (including the exhibit import rules), Prettier, Vitest and every npm script declared. The legacy site is preserved as the git tag `legacy-site` and removed from the working tree. `npm ci && npm run verify && npm run build` is green from this commit on, because every script whose real implementation lands later is a stub that prints `not implemented yet (WP-xx)` and exits 0.

## Notes
- `playwright-core` does not export `browsers.json`, so `require('playwright-core/browsers.json')` throws; resolve the file by path as in Commands (ARCHITECTURE §1.4).
- `@lhci/cli@0.15.1` hard-pins lighthouse 12.6.1; never add a standalone `lighthouse`. If an install script tries to download a browser, run with `PUPPETEER_SKIP_DOWNLOAD=1` (keep the preset `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`) and say so in the report.
- TypeScript 7 is blocked by the typescript-eslint peer range (`<6.1.0`). React must stay below 19.4 for `@react-three/fiber` 9.8.2.
- `prettier --check .` would fail on the R0 docs; that is why `docs/`, `CLAUDE.md`, `OWNERS.json` and `review/` are in `.prettierignore`.
- Vite 8 uses `build.rolldownOptions` (the `rollupOptions` alias is deprecated).
- `vite build --ssr src/entry-server.tsx --outDir dist-ssr` must succeed on the stub; keep the stub importable.
- `.npmrc` `save-exact=true` matters for later `npm install <pkg>` calls by R10; the `~` ranges above are deliberate and written by hand.
- The boot script stub must produce no output that breaks the CSP hash later: an empty `<script></script>` is fine until WP-10.
